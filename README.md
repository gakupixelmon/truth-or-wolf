# TRUTH OR WOLF

関数合成を推理するメイン版と、記号論理学で議論するクラシック版を収録したブラウザゲームです。

## 起動

```bash
npm start
```

ブラウザで `http://localhost:4173` を開いてください。初回だけ `npm install` が必要です。

## オンライン部屋

メインの関数人狼版は、部屋コードとパスワードを使ったオンライン対戦に対応しています。

- 「部屋を作る」で部屋を作成し、表示された6桁コードとパスワードを共有する
- 待機画面の部屋番号とパスワードはコピーボタンでワンタップ／ワンクリックでコピーできる（パスワードは作成者にだけ表示）
- 参加者は同じURLを開き、「部屋に入る」からコード・パスワードを入力する
- 部屋作成時に4〜12人、人狼1〜3人（人数に応じた上限）を設定でき、足りない席はCPUが担当する
- ロビーでは部屋主が参加人数を変更でき、ゲーム終了後は同じ部屋で再戦できる
- 観測と投票は各プレイヤーから同時に受け付け、全員分が揃ってから次へ進む。秘密関数や役職は本人以外に送信されない
- ゲーム中に参加者が退出・切断した場合は、残りの参加者を保護するためゲームを終了する

オンライン版を公開する場合は、`npm start` でこのNode.jsサーバーを起動できるRender、Railway、Fly.ioなどのWebサービスを使用してください。サーバーは `PORT` 環境変数を使い、外部公開時は `0.0.0.0` で待ち受けます。Vercelの静的ホスティングだけでは、Socket.IOによる部屋同期を維持できません。

### Renderの自動デプロイ

リポジトリには [render.yaml](./render.yaml) を用意しています。RenderでGitHubリポジトリを接続し、`feature/gakupixelmon` ブランチを選択してWeb Serviceを作成すると、以後そのブランチへpushするたびに自動でデプロイされます。

Renderの画面では次を確認してください。

- **Auto-Deploy**：`Yes` または `On commit`
- **Build Command**：`npm ci`
- **Start Command**：`npm start`
- **Instance Type**：`Free`（表示される場合）

コードを更新した後は、次の3コマンドだけでデプロイが始まります。

```bash
git add .
git commit -m "変更内容"
git push origin feature/gakupixelmon
```

## 関数人狼（メイン版）

- 部屋コードとパスワードで4〜12人がオンライン参加でき、空席はCPUが担当
- 部屋主はロビーのルール設定画面で参加人数、人狼人数、恒等関数 `y = x` の有無、襲撃時の関数推測の有無を変更できる
- 一次・二次・三次関数を使用し、入力点`0〜6`で計算する（剰余演算は行わない）
- 人狼関数 `W` の定義は全員に公開され、設定した人数の元人狼が `F = W` を共有する
- 市民は個別の秘密条件で `F自分 ∘ F指名相手` を評価し、`F自分 ∘ W` の結果と比較する
- 符号を公開するときは観測符号と目標符号の両方を公開する。人狼は自分の観測で目標符号（正・負・零）を選択できる
- 各市民の検査には複数人の候補が残り、一人の結果では元人狼を断定できない
- 全市民の異なる検査を組み合わせると、元人狼候補へ絞り込めるよう配役を自動調整
- 襲撃された市民の関数は秘密裏に `W ∘ F` へ変化する
- 人狼は市民側に存在する関数の種類一覧だけを知り、誰がどの関数かは知らない
- 複数人狼を設定した場合、人狼陣営は同じ `W` を共有し、投票と夜襲撃は陣営で1つの選択を共同で行う
- 襲撃時は対象者を選んだ後に関数を1つ推測し、対象の元関数と一致した場合だけ `W ∘ F` が成立する（外れた襲撃では感染しない）
- 襲撃時の関数推測を無効にした場合は、対象を選ぶだけで `W ∘ F` が成立する
- 襲撃済み市民は感染に気づかず市民として行動するが、投票だけは人狼陣営と同じ対象へ置換
- 追放されたプレイヤーの関数と秘密条件の代入値は、追放直後に生存中の人狼プレイヤーだけへ通知される（市民には公開されない）
- 元人狼を全員追放すれば市民勝利
- 生存中の人狼と襲撃済み市民が生存者の過半数を超えれば人狼勝利

### 管理者モード

管理者モードの鍵はソースコードに書かず、`.env` またはデプロイ先の環境変数 `TRUTH_OR_WOLF_ADMIN_KEY` に設定します。ローカルでは `.env.example` を `.env` にコピーして値を変更します。鍵を名前欄へ入力して部屋を作成すると、管理者用の設定画面が表示されます。`.env` は `.gitignore` でGitHubへの登録対象外です。

旧バージョンは `http://localhost:4173/classic.html` からプレイできます。

### コード構成（共同開発向け）

メイン版の画面とルールは、変更箇所が衝突しにくいように分離しています。

- `function-app.js`：状態、描画の切り替え、Socket.IO の初期化だけを行うエントリーポイント
- `function-ui/views.js`：通常ゲームの画面表示
- `function-ui/tutorial.js`：チュートリアル画面とチュートリアル専用イベント
- `function-ui/events.js`：フォーム、ボタン、Socket.IO イベントの接続
- `function-ui/format.js`：HTMLエスケープ、符号・フェーズ表示
- `rules/functions.js`：関数ライブラリ、秘密条件、偽陽性を含む配役バランス
- `rules/investigation.js`：合成観測、公開結果、CPUの事後確率更新
- `rules/voting.js`：CPU投票、感染者の投票置換、投票集計
- `rules/infection.js`：夜の襲撃と秘密合成
- `rules/victory.js`：市民側・人狼側の勝利条件
- `rules/constants.js`：人数、フェーズ、共通定数

新しいルールを追加するときは、該当する `rules/*.js` に純粋な関数として実装し、`function-game.js` の薄いメソッドから呼び出してください。画面文言や選択肢は `function-ui/views.js`、Socket.IO の送受信は `function-ui/events.js` を変更します。

## クラシック論理版

- プレイヤー1人 + CPU 6人
- 人狼1、占い師1、狩人1、市民4をゲームごとに無作為配役
- 発言は `P`, `¬P`, `P∧Q`, `P∨Q`, `P→Q`, `P↔Q` の選択式
- 論理式の `C(x)` は通常の市民役だけでなく、占い師・狩人を含む「市民陣営」を表す（`C(x) ↔ ¬W(x)`）
- 各人はちょうど1役職、特殊役職は各1人という公理を含めてSAT判定
- 過去発言と新しい命題が充足不能なら、投票を待たずプレイヤーを即時追放
- 各CPUは各人物について `P(人狼) / P(占い師) / P(狩人) / P(通常市民)` の個別事後分布を保持
- CPUごとに事前分布と話者への信頼度が異なり、同じ発言からも異なる事後確率を計算
- 人狼以外のCPUは原則として自身が62%以上で真だと考える命題を発言
- 82%以上の確実な足場を得た後は、28%の確率で「この発言者は占い師ではないか」などの不確かな仮説も発言
- 村陣営は各自の `P(人狼)` が最大の対象へ投票（同率のみ無作為）
- 占い・護衛・襲撃を含む昼夜サイクルと陣営勝敗を実装
- 占い結果は `人狼 / 人狼ではない` の二値だけで、詳細役職は非公開
- 初日は人狼を除外した無作為占い（必ず白判定）から開始

役職の公開結果はCPUの確率には反映されますが、発言の「嘘」と形式的な「矛盾」を区別するため、プレイヤーの論理式には自動追加されません。

## 共有について

このディレクトリはAPIキーや認証情報を含まず、そのままZIPで共有できます（`node_modules` は含まれないため、受け取った側で `npm install` を実行してください）。画面も外部フォントへ通信しません。`npm start` は既定で外部公開可能な `0.0.0.0` に待ち受けるため、ローカルだけで使う場合は `HOST=127.0.0.1 npm start` としてください。

今後秘密情報や個人データを追加した場合は、ZIP作成前に `.env`、ログ、OSの隠しファイルなどを除外してください。
